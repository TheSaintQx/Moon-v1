# Тестирование Moon Assistant 1.1.0

Два уровня: локальные тесты (без облака, без сети, без секретов) и проверка
живого стенда после загрузки архивов.

---

## 1. Локальные тесты

Нужен только Node.js 22. Ни `npm install`, ни ключей, ни доступа в интернет.

```bash
node tests/kb.test.js        # база знаний
node tests/vision.test.js    # vision
node tests/skill.test.js     # навык
node tests/adapter.test.js   # асинхронный адаптер навыка
```

Ожидаемый вывод:

```
66/66 проверок пройдено
83/83 проверок пройдено
27/27 проверок пройдено
14/14 проверок пройдено
```

Код возврата `0` — всё прошло, `1` — есть падения (в выводе строки `FAIL`).

### Как устроен стенд

`tests/fake-s3.js` подменяет `globalThis.fetch`:

- `storage.yandexcloud.net` — Object Storage в памяти (GET/PUT/404/412,
  честные `etag`, поэтому проверяется CAS);
- остальные хосты — только если явно смонтированы (`s3.mount(host, fn)`),
  иначе запрос падает с `network blocked in tests`.

`tests/fake-wiki.js` — MediaWiki API: `siteinfo`, `parse`, `search`,
`generator=search`, `generator=allpages` с `gapcontinue`, `pageids`,
`titles`, `recentchanges`. Поиск повторяет поведение вики: по префиксу
и словоформам («персонажи» находит «персонаж»).

База знаний и модель в тестах vision подменяются через `s3.mount` —
`kb.test` и `ai.api.cloud.yandex.net`.

### Что покрыто

| Набор | Проверки |
| --- | --- |
| `kb.test.js` | быстрый и полный режим, намерения, сравнение сущностей, прогрев (ok/partial/маленькая вики/занято/refresh/замок), выдача по намерению, готовность базы, случай «Джуди Альварес» (биография вместо хвоста, wikitext, старые данные), перевод запроса, универсальность (discover → register → warm → кросс-язычный вопрос), курсор синхронизации, слияние индекса, refresh по `revid` |
| `vision.test.js` | `answer_ready`, подтверждение показа, `?state=1`, кэш, контекст уточнений, кадры, смена игры, повтор модели, диагностика, токен заголовком, зависший прогрев, часовая копия, два этапа (короткий ответ → разбор → `?deep=1` без пересчёта → `ack` по стадии → неудачный разбор не стирает короткий) |
| `skill.test.js` | мгновенный ответ, ожидание с подсказкой, «ну что там», прогресс, «подробнее» (готов / ещё считается / без вопроса), смена игры и прогрев |
| `adapter.test.js` | перехват по `X-Moon-Token` и по `?token=`, отсутствие перехвата без токена и для выбора игры, отсутствие зацикливания на `?integration=async`, проброс ошибки платформы, чтение заголовков в трёх формах |

### Проверка содержимого архивов

Тесты умеют грузить модуль из архива — так проверяется именно то, что
уедет в облако:

```bash
KB_MODULE="$PWD/dist/moon-knowledge-engine/index.js" node tests/kb.test.js
VISION_MODULE="$PWD/dist/moon-vision/moon-vision-core.js" node tests/vision.test.js
SKILL_MODULE="$PWD/dist/moon-skill/moon-skill-core.js" node tests/skill.test.js
```

### Сборка и контрольные суммы

```bash
./tools/package.sh
cd dist && sha256sum -c SHA256SUMS.txt
```

Скрипт печатает таблицу «функция — версия — размер — sha256» и падает,
если какого-то файла нет.

## 2. Проверка живого стенда

Подставь свой токен вместо `<AUTH_TOKEN>` (он же `MOON_TOKEN` в навыке
и `KB_TOKEN` в базе знаний — это разные значения, см. таблицу переменных
в `README_RU.md`).

### 2.1. Живость

```
https://functions.yandexcloud.net/d4el6hpg7nh0cui52kd2?ping=1&token=<AUTH_TOKEN>
https://functions.yandexcloud.net/d4ekva50kru609d2jg6s?ping=1&token=<KB_TOKEN>
```

Ожидается `{"status":"pong","version":"4.1.0"}` и версия `0.9.0`.

### 2.2. База знаний (вкладка «Тестирование» в консоли)

```json
{"action":"register","game":"Hollow Knight","wikiApi":"https://hollowknight.fandom.com/api.php"}
{"action":"warm","game":"Hollow Knight"}
{"action":"search","game":"Hollow Knight","query":"кто такая хорнет","fast":true}
```

Что смотреть:

- `warm.status` — `ok` или `partial`; `warm.pages` — сколько статей легло;
- `warm.ready` — `true`, если статей и разделов достаточно для быстрых ответов;
- в `search` — `warm` всегда объект, `results[].section` показывает раздел,
  откуда взята выдержка.

### 2.3. Два этапа

1. Задай вопрос голосом или через `?ask=`.
2. `?answer=1&qid=<QID>` → `"stage":"quick"`, `"final":false`,
   `"deep_pending":true`.
3. `?deep=1&qid=<QID>` → `"stage":"deep"`, `"final":true`, текст длиннее.
4. Повтори шаг 3 — ответ вернётся сразу, без нового поиска.

### 2.4. Диагностика

```
https://functions.yandexcloud.net/d4el6hpg7nh0cui52kd2?diag=1&token=<AUTH_TOKEN>
```

| Поле | Норма |
| --- | --- |
| `ver` | `4.1.0` |
| `frame_age_s` | меньше 120, иначе экран не идёт |
| `warm.status` | `ok` для названной игры |
| `answers.quick_ready` / `answers.deep_ready` | растут после вопросов |
| `deep.enabled` | `true` |
| `last_model_error` | `null` или понятный код |
| `state_bytes` | меньше 300 000 |

### 2.5. Навык целиком

1. «Сменить игру» → «Hollow Knight» → «Принято, игра: …».
2. «Кто такая Хорнет» → короткий ответ.
3. «Подробнее» → разбор.
4. «Ну что там» после короткого ответа → тоже разбор.
5. Два одинаковых вопроса подряд → второй отвечается мгновенно (кэш).

### 2.6. Отсутствие утечек

```
?diag=1
```

В ответе только флаги `kb.url`, `kb.token`, `model.key` — `true/false`.
Ни одного значения ключа. В логах функций токенов тоже быть не должно:
навык передаёт его заголовком, а не в адресе.

## 3. Чего локальные тесты не проверяют

- Реальные задержки MediaWiki и модели.
- Лимиты одновременных вызовов функций в облаке.
- Поведение Алисы и оверлея на устройстве.
- Сборку APK: в этой среде нет Android SDK и JDK.

Эти пункты закрываются только прогоном на живом стенде по разделу 2.
