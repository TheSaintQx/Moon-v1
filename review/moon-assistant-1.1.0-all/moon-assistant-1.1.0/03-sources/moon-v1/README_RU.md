# Лунный Ассистент — README_RU

Голосовой игровой ассистент для Алисы: знания по любой игре, анализ кадров
с телефона и оверлей поверх игры. Релиз **1.1.0**.

- `moon-knowledge-engine` **0.9.0** — вики → индекс → выдержки;
- `moon-vision` **4.1.0** — кадры, два этапа ответа, кэш, оверлей;
- `moon-skill` **10.1** — навык Алисы.

Ноль npm-зависимостей, Node.js 22, точка входа везде `index.handler`.
Списка поддерживаемых игр нет: вики находится по названию.

---

## 1. Состав поставки

```
dist/
  moon-knowledge-engine-v1.1.0.zip
  moon-vision-v1.1.0.zip
  moon-skill-v1.1.0.zip
  SHA256SUMS.txt
```

Внутри каждого архива: `index.js` (точка входа), файлы ядра, `VERSION`.
Лишнего не требуется — архивы самодостаточны.

Проверка целостности:

```bash
cd dist && sha256sum -c SHA256SUMS.txt
```

## 2. Установка

### 2.1. Порядок

1. `moon-knowledge-engine` — нужен двум другим.
2. `moon-vision`.
3. `moon-skill`.

Между шагами ничего не ломается: изменения совместимы в обе стороны.

### 2.2. Для каждой функции

1. Консоль → **Cloud Functions** → нужная функция.
2. **«Редактировать»** (или ⋯ → «Загрузить код») → выбрать архив.
3. Проверить, что не изменились:

| Параметр | `moon-skill` | `moon-vision` | `moon-knowledge-engine` |
| --- | --- | --- | --- |
| точка входа | `index.handler` | `index.handler` | `index.handler` |
| среда | `nodejs22` | `nodejs22` | `nodejs22` |
| таймаут | 5 с | 2 мин | 1 мин |
| память | 128 МБ | 256 МБ | 512 МБ |
| сервисный аккаунт | — | нужен доступ к бакету | нужен доступ к бакету |

4. Сохранить изменения.

Переменные окружения при обновлении **не трогать** — они уже настроены.

### 2.3. Обновление с 1.0.0

Порядок тот же. Данные в бакете (`state.json`, `kb/`) формат не меняли:
новые поля (`quick`, `fastDone`, `deepKickedAt`, `ackedStage`, `warmStatus`,
`warmSections`) старые версии просто игнорируют. APK обновлять не нужно.

## 5. Что изменилось в 1.1.0

Коротко (полностью — в `CHANGELOG.md`, разбор дефектов — в `AUDIT_RU.md`):

- **два этапа ответа**: короткий сразу, разбор по «подробнее»;
- **асинхронный путь навыка снова работает** (токен искали только в адресе);
- **выдержки берутся из нужного раздела**: интервики-ссылки и служебные
  блоки вырезаются, «Биография» больше не проигрывает хвосту статьи;
- **готовность базы** считается по статьям и разделам, `warm` всегда объект;
- **`reasoning_effort`** отправляется только по требованию;
- **`refresh`** — обновление базы по `recentchanges` без полного перечитывания;
- **`syncGame`** больше не затирает индекс;
- **замок прогрева** снимается при исключении;
- **вика ищется** сначала прямыми кандидатами, потом веб-поиском;
- **токен в APK** больше не хранится в репозитории.

## 6. Известные ограничения

- Реплика Алисы — около 4,5 с. Разбор в неё не влезает и приходит
  по «подробнее» или через оверлей.
- Разбор — отдельная invocation: это дополнительный вызов функции
  на каждый вопрос.
- Первый вопрос по новой теме не мгновенный: нужен вызов модели.
- Название игры должно совпадать с вики («Minecraft», а не «майн крафт»),
  иначе это будет другая база.
- Прогрев большой вики идёт до 35 с; первый вопрос может собраться полным
  поиском.
- Если в вики нет раздела с ответом, разбор честно вернёт `unk`,
  короткий ответ останется как есть.
- Логи функций в облаке выключены — диагностика идёт через `?diag=1`.

## 7. Откат

1. `moon-skill` → 10.0.
2. `moon-vision` → 4.0.0.
3. `moon-knowledge-engine` → 0.8.0 (если проблема в базе).

В каждой функции есть **«История версий»**: прежние версии в статусе
`Obsolete`, нужную можно сделать активной. Данные в бакете совместимы
в обе стороны. Записи в статусах `quick_ready`/`deep_ready` vision 4.0.0
не узнаёт (покажет как просроченные), поэтому vision откатывай вместе
с навыком.

## 8. Безопасность — обязательно

Значения `ACCESS_KEY_ID`, `SECRET_ACCESS_KEY`, `AUTH_TOKEN`, `MOON_TOKEN`,
`KB_TOKEN`, `YC_API_KEY` были в открытом виде (в репозитории и в переписке).
Из истории git они не исчезают — считай их скомпрометированными.

1. Перевыпусти статический ключ Object Storage.
2. Обнови `ACCESS_KEY_ID` и `SECRET_ACCESS_KEY` в vision и knowledge-engine.
3. Новый общий токен → `AUTH_TOKEN` (vision) = `MOON_TOKEN` (skill).
4. Новый `KB_TOKEN` → vision и knowledge-engine (одинаково).
5. Перевыпусти `YC_API_KEY` в AI Studio и обнови в vision.
6. Токен для APK больше не лежит в коде: задай его через `buildConfigField`
   или `TOKEN_FALLBACK` и пересобери приложение.
