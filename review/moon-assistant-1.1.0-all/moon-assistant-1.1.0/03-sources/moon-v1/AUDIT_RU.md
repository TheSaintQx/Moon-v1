# Аудит Moon-v1 и что по нему исправлено

Документ фиксирует результаты разбора репозитория `TheSaintQx/Moon-v1`
по главному техническому заданию и перечень фактически внесённых изменений.
Это не список рекомендаций: каждый пункт ниже уже закрыт кодом и проверен
локальным тестом.

Дата разбора: 9 ноября 2026. Базовая точка: коммит `87d0280`.
Итоговая сборка: релиз **1.1.0** (`moon-knowledge-engine` 0.9.0,
`moon-vision` 4.1.0, `moon-skill` 10.1).

## 2. Найденные дефекты

### 2.1. Асинхронный путь навыка был мёртвым кодом (критично)

`moon-skill-index.js` перехватывал POST вопроса только при наличии
`?token=` в адресе:

```js
if (requestUrl && ... === CLOUD_URL && requestUrl.searchParams.has('token'))
```

С версии 10.0 ядро отправляет токен заголовком `X-Moon-Token`
(`moon-skill-core.js`, `cloudFetch`), поэтому условие никогда не выполнялось:
перехват не срабатывал, `?integration=async` не вызывался, весь задуманный
асинхронный путь не работал, а вопрос каждый раз уходил в синхронный POST.

**Исправлено:** адаптер 1.1 ищет токен и в заголовке, и в адресе
(совместимость), сам себя не перехватывает (`?integration=async`),
а ошибку запуска не выдаёт за принятую задачу. Проверка — `tests/adapter.test.js`.

### 2.2. Ответ на вопрос «кто такая Джуди Альварес» брался из хвоста статьи (критично)

`stripWikitext` превращал интервики-ссылки `[[en:Judy Alvarez]]` в обычный
текст. Хвост статьи («en:Judy Alvarez, fr:Judy Alvarez, …») попадал в
выдержку, получал высокий вес по совпадению имени и выигрывал у раздела
«Биография».

**Исправлено:**
- интервики-ссылки удаляются целиком;
- служебные разделы («Примечания», «Ссылки», «Навигация», «Галерея», `trivia`)
  отбрасываются при сборке записи статьи;
- у выдержки появился штраф за «мусорность» (`boilerplateRatio`) и бонус за
  попадание в раздел, подсказанный намерением вопроса;
- нарезка текста идёт по разделам статьи, а не по 1400 знаков подряд,
  поэтому раздел не разрывается посередине.

Проба после правки: выдержка выбирается из раздела «Биография»,
оценка 6,74, группа `biography`.

### 2.3. `warm: null` в ответе поиска (средне)

Если прогрев ещё не начинался, поле `warm` приходило как `null`, и vision
не мог отличить «база не готова» от «поля нет».

**Исправлено:** `warmStatusOf()` всегда возвращает объект
`{status, ready, pages, storedPages, builtAt, ageS, sections, language, genre, truncated, source}`.
Готовность считается по числу статей и разделов, а не по наличию `manifest.json`.

### 2.4. `reasoning_effort: 'none'` отправлялся всегда (средне)

Параметр необязательный и принимается не всеми моделями Yandex AI.
При отказе модели ответ деградировал до «не могу подтвердить».

**Исправлено:** параметр уходит только если администратор задал
`MOON_REASONING`. По умолчанию его в теле запроса нет.

### 2.5. Не было второго, более полного ответа на тот же вопрос (средне)

Один проход «поиск + модель» на вопрос: либо коротко, либо ничего.
Углубить ответ без повторного вопроса было нельзя, а повторный вопрос
заново поднимал вики и модель.

**Исправлено:** у вопроса теперь явные состояния
`pending → processing_fast → quick_ready → processing_deep → deep_ready`
(плюс `failed`/`expired`/`superseded`/`cancelled`).

- короткий ответ сохраняется отдельно (`rec.quick`) и отдаётся сразу;
- разбор доготовляется отдельной invocation и **не затирает** короткий ответ;
- `?deep=1` отдаёт готовый разбор или продолжает прерванный;
- подтверждение показа (`ack`) учитывает стадию: если игрок подтвердил
  короткий ответ, разбор всё равно покажется один раз;
- если разбор не удался, короткий ответ остаётся (поле `deepFallback`).

### 2.6. `syncGame` затирал индекс (средне)

`syncGame` писал индекс целиком (`writeJson(indexKey(id), index)`), поэтому
параллельная запись (например, прогрев) терялась.

**Исправлено:** запись через `writeIndexMerged()` со слиянием по статьям.

### 2.7. Не было инкрементального обновления базы (средне)

База обновлялась только полным перечитыванием. Для большой вики это дорого,
а устаревшие статьи жили в индексе неограниченно долго.

**Исправлено:** действие `refresh` — `list=recentchanges`, сравнение `revid`
с сохранённым `revisionId`, перечитывание только изменившихся статей
пачками по 8. Возвращает `{checked, updated, addedNew, newTitles, errors}`.

### 2.8. Замок прогрева не снимался при исключении (низко)

Если `warmGame` падал, ключ `warmLock` оставался занятым до истечения срока,
и повторный прогрев откладывался.

**Исправлено:** снятие замка в `finally`, частичный результат пишется
после каждого шага (`warm.json` + поля manifest), статус `ok`/`partial`/`no_evidence`.

### 2.9. Поиск вики зависел только от веб-поиска (низко)

`discover` угадывал вики через HTML-выдачу DuckDuckGo: медленно и хрупко.

**Исправлено:** сначала проверяются прямые кандидаты
(`<slug>.fandom.com`, `<slug>.wiki.gg`, оба варианта `api.php`), и только
если они не ответили — веб-поиск.

### 2.10. `?progress=1` знал только статус `done` (низко)

Навык проверял `pr.status === 'done'`, а vision отдавал сырой статус записи.
После появления двух этапов это стало бы вторым источником рассинхронизации.

**Исправлено:** `?progress=1` отдаёт `status:'done'` для любого готового
текста и отдельные поля `stage`/`final`/`deep_pending`.

## 3. Что добавлено в навык (v10.1)

- короткий ответ озвучивается сразу, с предложением «скажи „подробнее“»;
- «подробнее», «поглубже», «разбор», «детали» — забирают разбор того же
  вопроса (`?deep=1`), не запуская поиск заново;
- «ну что там» после короткого ответа тоже забирает разбор;
- если разбор ещё считается — Алиса говорит об этом, а не молчит;
- «подробнее» без вопроса — понятный отказ без обращения к серверу;
- состояние (`qid`, `cid`, `quickText`, `deepPending`) сохраняется между
  репликами, поэтому разбор не теряется при переходе хода.

## 5. Что осталось за рамками кода

- **Ключи.** В репозитории и в переписке фигурировали реальные ключи
  (API-ключ Yandex AI, ключи Object Storage, `AUTH_TOKEN`). Их нужно
  перевыпустить в консоли Yandex Cloud: из истории git они не исчезают.
- **Проверка в живом облаке.** Задержки вики, фактическая скорость модели
  и поведение Алисы на реальном устройстве кодом не проверяются.
  Для этого есть `?diag=1` и раздел «Как проверить после загрузки».
- **Публикация.** Прямой push в репозиторий невозможен: в среде сборки нет
  авторизации GitHub. Изменения переданы коммитами и git-бандлом.
