# Moon v1 — Лунный Ассистент

Три функции Yandex Cloud, которые вместе дают голосового игрового ассистента
для Алисы: знания по игре, анализ кадров с телефона и оверлей поверх игры.
Списка поддерживаемых игр нет: вики находится по названию, база знаний
создаётся сама.

Релиз **1.1.0**: `moon-knowledge-engine` 0.9.0, `moon-vision` 4.1.0,
`moon-skill` 10.1.

## Что даёт релиз 1.1.0

- **Ответ в два этапа.** Короткий ответ приходит сразу, полный разбор —
  по слову «подробнее» или на «ну что там». Разбор не затирает короткий
  ответ и не заставляет задавать вопрос заново.
- **Асинхронный путь навыка снова работает.** Адаптер искал токен только
  в адресе, а ядро с v10.0 шлёт его заголовком — перехват не срабатывал.
- **Выдержки берутся из нужного раздела.** Интервики-ссылки и служебные
  разделы («Примечания», «Ссылки», «Галерея») больше не попадают в ответ
  и не выигрывают у «Биографии».
- **Понятная готовность базы.** `warm` в ответе поиска всегда объект,
  готовность считается по числу статей и разделов.
- **Обновление базы без полного перечитывания** — действие `refresh`
  по `recentchanges` и `revid`.
- **`reasoning_effort` только по требованию** — параметр не ломает модели,
  которые его не принимают.
- **Смена игры на стриме, повтор при сбое модели, `?diag=1`, часовая копия
  состояния, токен заголовком** — из релиза 1.0.0, сохранено без изменений.

## Структура

| Файл | Что это |
| --- | --- |
| `moon-skill-index.js` + `moon-skill-core.js` | навык Алисы; адаптер переводит вопрос в асинхронный вызов |
| `moon-vision-index.js` + `moon-vision-core.js` | зрение, база знаний, два этапа ответа, `answer_ready` для оверлея |
| `moon-knowledge-index.js` | база знаний: вики → индекс в Object Storage → поиск с выдержками |
| `tests/` | локальные тесты с подменой S3, вики, базы знаний и модели |
| `tools/package.sh` | собирает `dist/*-v1.1.0.zip`, `dist/SHA256SUMS.txt` и `VERSION` в каждом архиве |
| `README_RU.md` | установка, таблица переменных окружения, обновление, откат |
| `ARCHITECTURE.md` | архитектура, потоки данных, состояния, принятые решения |
| `ТЕСТИРОВАНИЕ.md` | локальные тесты и проверка живого стенда |

| `CHANGELOG.md` | история версий и известные ограничения |

## Как это работает для любой игры

1. Игрок называет игру — навык отправляет её в `moon-vision`.
2. `moon-vision` вызывает `?warm=1`: база знаний по названию находит вики
   (сначала прямые кандидаты `<slug>.fandom.com` / `<slug>.wiki.gg`,
   затем веб-поиск), регистрирует игру и загружает обзорные статьи
   (персонажи, локации, предметы, механики, сюжет) в локальный индекс.
   Если прогрев не успел — его запускает первый кадр стрима или первый `?poll=1`.
3. Вопрос получает намерение (`characters`, `locations`, `compare`, …),
   база подмешивает обзорную статью и выдержки из нескольких статей,
   а модель склеивает из них короткий ответ.
4. Параллельно доготовляется разбор: полный поиск по вики, больше источников,
   до 900 знаков. Он ждёт игрока в `?deep=1`.

База хранится в `kb/games/<slug>/`; отдельного списка игр в коде нет.

## Сборка архивов

```bash
./tools/package.sh
```

Скрипт печатает таблицу «функция — версия — размер — sha256» и кладёт
`dist/SHA256SUMS.txt`. В архиве точка входа всегда `index.js`, как ждёт
Yandex Cloud.

## Проверка

```bash
node tests/kb.test.js
node tests/vision.test.js
node tests/skill.test.js
node tests/adapter.test.js
```

Тесты работают без облака и без секретов: Object Storage заменён памятью,
внешняя сеть заблокирована, вики, база знаний и модель подменены.

Проверить именно то, что лежит в архивах:

```bash
KB_MODULE="$PWD/dist/moon-knowledge-engine/index.js" node tests/kb.test.js
VISION_MODULE="$PWD/dist/moon-vision/moon-vision-core.js" node tests/vision.test.js
SKILL_MODULE="$PWD/dist/moon-skill/moon-skill-core.js" node tests/skill.test.js
```

Покрытие релиза 1.1.0: база знаний — 66 проверок, vision — 83,
навык — 27, адаптер — 14.

Быстрая проверка живого стенда — `?diag=1` у moon-vision: версия, игра,
прогрев, два этапа ответа, последние ответы с временем и источником,
ошибки модели.
